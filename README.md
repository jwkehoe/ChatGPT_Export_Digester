# ChatGPT Archive Digester

This utility exists because ChatGPT export data is optimized for machines, not humans. The export is a graph of nodes, mixed metadata, and file references that often needs aggressive cleaning before it is readable or analyzable. The goal is to produce a human-friendly, stable layout organized by conversation ID and to merge multiple overlapping exports without clobbering or duplicating messages.

## Why This Exists
- ChatGPT exports are disjointed for human analysis (graph nodes + sparse text).
- Multiple exports often overlap but are incomplete; a single export rarely contains a conversation's full lifetime.
- This tool consolidates messages across multiple zip exports, creates a linear transcript, and copies any referenced assets into each conversation folder.
- A companion script renames folders to human-readable titles and writes a mapping of conversation ID → title.

## What It Produces
For each conversation:
- `conversation.md` (human-readable transcript)
- `messages.jsonl` (normalized messages, one per line)
- `assets/` (copied referenced files)
- `assets_manifest.json` (resolved/unresolved asset references)

Global outputs:
- `index.json` (summary + pointers to each conversation)
- `unresolved_assets_report.jsonl` and `unresolved_assets_summary.json`
- `rename_map.json` and `id_title_map.json` generated by the renamer when run

## Export Data Format (Analysis Summary)
ChatGPT exports are zip archives with a consistent core set of files:
- `conversations.json`: array of conversations (primary source for the digester).
- `user.json`: account metadata.
- `shared_conversations.json`: list of shared conversation references.
- `message_feedback.json`, `shopping.json`: often empty arrays in exports.
- `chat.html`: rendered transcript that can include private-use Unicode asset markers.
- Binary attachments referenced by messages.

Key structural notes from `conversations.json`:
- Top-level is a list of conversations.
- Each conversation contains a `mapping` (node graph) keyed by node id.
- Each node contains an optional `message` object with `author`, `content`, and `metadata`.
- `content` varies by `content_type` (text, code, execution_output, multimodal_text, etc.).
- Asset references appear in `metadata.attachments` and in `content.parts` (asset pointers).

Full details are documented in:
- `chatgpt_conversations.schema.json`
- `ChatGPT_Export_Schema_Analysis.md`

## Core Script
`chatgpt_export_digester.py`

### Merge overlapping exports (recommended)
This consolidates messages across multiple exports without duplication.

```
python3 chatgpt_export_digester.py \
  --input-dir ChatGPT_Exports \
  --output-dir ChatGPT_Digested \
  --merge-overlaps
```

### Non-merge mode
Processes each export independently (with optional conversation-level dedupe).

```
python3 chatgpt_export_digester.py \
  --input-dir ChatGPT_Exports \
  --output-dir ChatGPT_Digested
```

Running `python3 chatgpt_export_digester.py` with no options now prints the detailed option reference, reason text, and example commands before exiting, giving you the context you need to pick flags.

### Useful options
- `--merge-overlaps` merge partial exports into consolidated conversations.
- `--include-all-branches` linearize all branches (default is active path only).
- `--no-dedupe` keep separate copies when not using merge mode.
- `--asset-strategy copy_per_conversation` (the only strategy today) copies every referenced file into the conversation-specific `assets/` folder and records resolved/unresolved metadata.
- `--input` can be repeated to pass explicit zip files.

## Rename Script
`rename_conversation_dirs.py`

Renames each conversation folder using the title from `conversation.md` and writes mapping files.

```
python3 rename_conversation_dirs.py \
  --root ChatGPT_Digested/conversations
```

Running the renamer with no options now prints its option reference and reasoning text before exiting so you can understand each flag before deciding.

Outputs:
- `ChatGPT_Digested/rename_map.json` (from → to, title, ID)
- `ChatGPT_Digested/id_title_map.json` (ID → title)

Optional flags:
- `--dry-run` preview without renaming.
- `--include-id` append the original folder ID to prevent collisions.

## Automation
A GitHub Actions workflow (`.github/workflows/ci.yml`) runs on pushes and pull requests to `main`. It installs any dependencies listed in `requirements.txt` (nothing beyond the standard library) and exercises both CLIs via `--help` across Python 3.10–3.12 to surface obvious issues before merging.
